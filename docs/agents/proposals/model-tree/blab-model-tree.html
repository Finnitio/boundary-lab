Why it scales

  • A new feature becomes a new node type, not another button in the command strip and another window.
  • The tree reads top to bottom in workflow order: Geometry, Meshes, System, Channels, Solve, Results. It doubles as a checklist.
  • State is visible where it matters: Interfaces is greyed out until the system has both region types, and Solve and Results show out of date after a model edit.
  • The tree mirrors the .blab.json project. The file format does not change.

What stays the same

  • Generate (F7), Solve (F5) and Stop (Shift+F5), now in a toolbar and on the matching nodes.
  • Solver backend and other app settings stay in Edit › Preferences; the Solve node only displays them.
  • Plot interactions: crosshair drag, right-click to compare with the previous solve, PNG export.
  • Several plots side by side. A plot group holds any number of plots, so today's dock layout becomes the default “Overview” group.

A possible migration path

  1. Tree plus stacked settings pages that host the existing dialog contents (the Regions, Boundaries, Interfaces, Components and Channels tables) without OK/Cancel.
  2. Graphics area that follows the selection, reusing the mesh preview's surface picking for highlights.
  3. Plot groups in place of fixed docks, and an undo stack. Undo is new work and the precondition for live editing.
